# v1.0.0

初の安定版リリース。`.env` 系ファイル 2 つを **環境変数ごとに** 比較する CLI ツール `envdiff` の全機能が揃いました。

通常の `diff` は行単位で比較するため、コメントや空行、記述順の違いがノイズとして差分に現れ、本当に知りたい「どの環境変数が違うのか」が埋もれてしまいます。envdiff はファイルを環境変数の集合として解釈し、キー単位で比較します。

## インストール

```bash
git clone https://github.com/tominaga-h/envdiff.git
cd envdiff
cargo install --path .
```

Rust 1.85 以降が必要（2024 edition）。

## 使い方

```
envdiff <A> <B> [OPTIONS]
```

```console
$ envdiff .env.example .env.local
┌──────────────┬────────────────────────────────┬───────────────────────────────────┬───────────┐
│ KEY          │ .env.example (A)               │ .env.local (B)                    │ STATUS    │
╞══════════════╪════════════════════════════════╪═══════════════════════════════════╪═══════════╡
│ APP_ENV      │ development                    │ production                        │ changed   │
├──────────────┼────────────────────────────────┼───────────────────────────────────┼───────────┤
│ API_KEY      │                                │ sk-live-abc123                    │ changed   │
├──────────────┼────────────────────────────────┼───────────────────────────────────┼───────────┤
│ DATABASE_URL │ postgres://localhost/myapp_dev │ postgres://prod.example.com/myapp │ changed   │
├──────────────┼────────────────────────────────┼───────────────────────────────────┼───────────┤
│ SENTRY_DSN   │ -                              │ https://xxx@sentry.io/1           │ only in B │
└──────────────┴────────────────────────────────┴───────────────────────────────────┴───────────┘

4 differences (3 changed, 0 only in A, 1 only in B)
A = .env.example, B = .env.local
```

`A` と `B` は単に第 1・第 2 引数であり、出力の A 列・B 列に対応するだけです。どちらかを「基準」として扱うことはなく、ツールがユーザーの意図を推測することもありません。

## 機能一覧

### 比較

各キーは必ず次の 4 状態のいずれかに分類されます。

| STATUS | 意味 |
| --- | --- |
| **changed** | 両方に存在し、値が異なる |
| **only in A** | A にのみ存在 |
| **only in B** | B にのみ存在 |
| **same** | 両方に存在し、値も同じ |

- `same` はデフォルトで非表示 — 100 個中 3 個違うときに 97 行のノイズを読ませない
- `only in A` と `only in B` を区別 — `.env.example` と `.env` を比べる典型ケースで、この 2 つの意味はまったく違う（設定漏れ vs 書き忘れ・残骸）
- 値が空文字の変数（`KEY=`）とキーの不在を区別 — テーブルでは空セルと `-`、JSON では `""` と `null`

### オプション

| オプション | 説明 |
| --- | --- |
| `--all` | 差分のない変数（`same`）も出力に含める |
| `--json` | JSON 形式で出力する |

`--all`（表示範囲）と `--json`（出力形式）は直交します。組み合わせて使え、互いの意味を変えません。

### 終了コード

`diff(1)` の慣習に従います。`diff` を置き換えても CI が壊れません。

| コード | 意味 |
| --- | --- |
| `0` | 差分なし |
| `1` | 差分あり |
| `2` | エラー（パースエラー、ファイル読み込み失敗、引数不正） |

乖離チェックが一行で書けます。

```sh
envdiff .env.example .env   # 乖離していれば exit 1
```

`--all` / `--json` / 警告は、終了コードの判定を変えません。

### JSON 出力

```console
$ envdiff --json .env .env.example
{
  "files": { "a": ".env", "b": ".env.example" },
  "summary": { "total": 3, "changed": 1, "only_in_a": 1, "only_in_b": 1, "same": 0 },
  "diffs": [
    { "key": "PORT",    "status": "changed",   "a": "3000", "b": "8000" },
    { "key": "APP_ENV", "status": "only_in_a", "a": "1",    "b": null },
    { "key": "DEBUG",   "status": "only_in_b", "a": null,   "b": "true" }
  ]
}
```

- キーの不在は `null`、値が空文字は `""` — 型で区別される
- `diffs[].a` / `.b` のキー名は `a` / `b` 固定。ファイル名をキーにすると入力によって JSON の形が変わり `jq` のクエリが書けなくなるため、実ファイル名は `files` に入る
- `summary.total` は差分の数（`same` は差分ではないので含まない）

差分の重要度をツールが判定しないため、選り好みは `jq` で行います。

```sh
envdiff --json .env.example .env | jq '.diffs[] | select(.status == "only_in_a")'
```

### パース仕様

`.env` に正式な仕様は存在しないため、独自の最小仕様を定めています。

| 入力 | 結果 |
| --- | --- |
| `KEY=VALUE` | `=` の**最初の出現**で分割（値に `=` を含められる） |
| `export KEY=VALUE` | `export` を剥がす |
| `# コメント` | 無視。ただしクォート内の `#` はコメントではない |
| `PORT="3000"` | `PORT=3000` と **`same`**（クォートを剥がす） |
| `KEY=foo"bar"` / `{"k": "v"}` | 素通し（そのクォートは値を囲んでいない） |
| `API_URL=${BASE_URL}/api` | 展開しない。`${` は単なる文字 |
| `KEY=` | 値が空文字の変数として**存在する**（「未設定」ではない） |
| `KEY`（`=` なし） | **パースエラー**（束縛が存在しない） |
| `=VALUE` | **パースエラー**（束縛される先がない） |

エスケープの解釈:

| クォート | 挙動 |
| --- | --- |
| `"..."` | `\n` `\r` `\t` `\\` `\"` のみ解釈 |
| `'...'` | 一切解釈しない（シェルと同じ規則） |

### 複数行の値

Rails の `master.key`、Firebase のサービスアカウント、GCP 認証情報などで実在する形式に対応します。

```env
PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----
MIIEpAIBAAKCAQEA...
-----END RSA PRIVATE KEY-----"
```

クォートが閉じないまま行が終わったら、閉じるまで次行以降を値として読み続けます。EOF まで閉じなければパースエラーで、メッセージはクォートの**開始行**を指します。

```
error: .env:12: quote opened here is never closed (reached end of file)
```

### 重複キーの警告

後勝ちで値を採用し、stderr に警告を出します。

```
warning: .env:14: duplicate key 'DB_HOST' (overrides value from line 9)
```

重複キーはほぼ確実にバグですが（書いた人は上の行が効くと思っている）、パースエラーにはしません。重複のせいで比較全体が失敗すると、本当に知りたかった差分にたどり着けないためです。警告は stdout ではなく stderr に出るため、パイプに影響しません。終了コードにも影響しません。

### 出力順序

キーは**ファイルに書かれている順**に並びます（アルファベット順にしない）。A に存在するキーを A の行番号順に並べ、その後ろに `only in B` のキーを B の行番号順で続けます。

ユーザーは差分を見た後に実ファイルを開いて直すため、書かれている順なら出力とファイルを上から突き合わせられます。

### 色

- **テーブルには色を付けない** — STATUS 列に既に `only in B` と書かれており色は情報を足さず、赤/緑は「悪い/良い」を含意してツールが差分の重要度を主張することになる
- stderr の warning / error にのみ色を付ける（`NO_COLOR` および stderr が非 TTY のときは無効化）

## 設計の考え方

判断に迷ったとき立ち返る一文があります。

> **envdiff は「何が書いてあるか」を比べるツールである。**

「実行時に最終的に何がセットされるか」を比べるツールではありません。この一文から次が導かれます。

| 判断 | 理由 |
| --- | --- |
| クォートを剥がす（`PORT=3000` と `PORT="3000"` は `same`） | クォートの有無は「書かれ方の違い」であって「書かれている内容の違い」ではない |
| 変数展開しない（`${FOO}` は `changed`） | 展開は実行環境に依存し、CI と手元で違う答えを出す比較ツールになる。また「片方はリファクタ済み、片方はハードコード」という人間が知るべき差分を握り潰す |
| 不正な行で即停止する | 読み飛ばすと「変数が片方にない」と誤報告し、ユーザーは実ファイルではなく envdiff のバグを疑う |
| エラーを exit 2 にする | exit 1 だと「差分を見つけた」と「読めなかった」が呼び出し側から区別できない |
| 差分の重要度を判定しない | 「これは設定漏れだから危険」といった主張はしない。選り好みは `--json` を `jq` に通して行う |

## スコープ外（MVP）

- サブコマンド（単一責務。`envdiff <A> <B>` のみ）
- 3 ファイル以上の比較
- 変数展開（`${FOO}`）
- 標準入力（`-`）からの読み込み
- 差分の重要度判定
- テーブル出力の色付け
