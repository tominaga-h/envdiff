# v1.1.0

`changed` 行の **値のどこが変わったか** を見えるようにしました。

v1.0.0 は「この変数が変わった」までしか言いませんでした。`DATABASE_URL` の 40 文字のうちホスト名だけが違うとき、STATUS 列は `changed` と言うだけで、どこを見ればいいかは目視で探すしかありませんでした。それはまさに知りたい情報です。

## インストール

```bash
git clone https://github.com/tominaga-h/envdiff.git
cd envdiff
cargo install --path .
```

Rust 1.85 以降が必要（2024 edition）。v1.0.0 から変更ありません。

## 何が変わったか

```console
$ envdiff .env.example .env.local
┌──────────────┬────────────────────────────────┬───────────────────────────────────┬───────────┐
│ KEY          │ .env.example (A)               │ .env.local (B)                    │ STATUS    │
╞══════════════╪════════════════════════════════╪═══════════════════════════════════╪═══════════╡
│ DATABASE_URL │ postgres://localhost/myapp_dev │ postgres://prod.example.com/myapp │ changed   │
│              │            ~~~~~~~~~~~~~~~~~~  │            ~~~~~~~~~~~~~~~~~~~~~  │           │
│              │            └ 赤 + 太字          │            └ 緑 + 太字             │           │
└──────────────┴────────────────────────────────┴───────────────────────────────────┴───────────┘
```

`postgres://` と共通部分は無加工のまま、**実際に違う部分だけ**が強調されます。A 側は赤、B 側は緑。

終了コード・STATUS 語彙・JSON の形は**一切変わりません**。強調も色も付加情報であり、v1.0.0 から移行して壊れるものはありません。

## 強調

### 対象は `changed` 行の値セルだけ

`only in A` / `only in B` の行には付けません。片側にキーが存在しない以上、比較対象がなく「値の中のどこが変わったか」が定義できないためです。値を丸ごと太字にすると「値の中のどこかが変わった」という誤読を招きますが、実際にはキーごと存在しないのであり、それは STATUS 列が言っています。`same` 行も定義上差分がないため付けません。

### 位置合わせには差分アルゴリズムが要る

先頭から 1 文字ずつ突き合わせる素朴な実装は、挿入・削除が入った時点で破綻します。

```
postgres://localhost:5432/db
postgres://db.prod:5432/db
```

`localhost`(9 文字) と `db.prod`(7 文字) は長さが違うため、以降の `:5432/db` は 2 文字ずれたまま比較され、**両者に同一で存在するのに差分と判定されます**。結果として値の大半が太字になり、「どこが違うか」を示すという目的が消えます。

共通部分列の検出に LCS（`similar` の文字粒度 Myers 差分）を使っています。

### LCS の結果をそのまま強調しない

LCS が返すのは **最小の編集** であって、人間が読みたい **まとまった塊** ではありません。値どうしは無関係な位置で文字をたまたま共有するため、素の結果は強調が砕けます。短い共通部分を差分に吸収してから強調しています。

## 色

**v1.0.0 の「テーブルに色を付けない」という決定を意図的に覆しました。**

v1.0.0 は 3 つの根拠で赤/緑を却下していました。決定を覆すにあたり、その 3 つを消さずにどう扱ったかを残します。

| v1.0.0 の根拠 | v1.1.0 での扱い |
| --- | --- |
| STATUS 列に既に書いてあり、色は情報を足していない | **覆した。この指摘は今も正しい。** 色は太字とまったく同じ文字に乗るため、太字が既に言っていること（「ここが違う」）を繰り返すだけで、新しい情報を足さない。**承知の上で採用した。** A/B の視覚的な区別が読みやすいという理由による。色が果たすのは情報伝達ではなく可読性の役割 |
| 赤/緑は「悪い/良い」を含意し、ツールが重要度を主張し始める | **覆した。** 赤 = A / 緑 = B は列の割り当てであって重要度の主張ではない、という立場を取る。ただし赤/緑がそう読まれうることは認める。「差分の重要度を判定しない」方針は**出力の内容**（STATUS 語彙・終了コード・サマリ）については従来どおり不変であり、色はそこに何も足さない |
| 赤緑は色覚特性上もっとも区別しにくい | **覆していない。この根拠は今も正しい。** 赤緑の色覚特性を持つ方には A 列と B 列の色が区別できない。それでも成立するのは、**色が唯一の手掛かりになる場面がないため**。太字が色とまったく同じ文字に乗っており、色が見えなくても差分位置は太字で分かる。A/B の区別は列位置・ヘッダー（`.env (A)` / `.env.example (B)`）・STATUS 列が担う。色が見えない読者は**手掛かりを 1 つ失うが、情報は 1 つも失わない** |

**差分文字だけを色付けする**（セル全体を色にしない）という選択は、この 3 つ目が生きたまま成立する理由そのものであり、偶然ではなく選択の結果です。

### 太字は残す

太字と色は同じ文字に乗るため冗長に見えますが、**消える条件が違います**。

| 消える条件 | 太字 | 色 |
| --- | --- | --- |
| `NO_COLOR` / パイプ・リダイレクト | 消える | 消える |
| bold ウェイトを持たないフォント | **消える** | 残る |
| 色覚特性（P 型 / D 型） | 残る | **区別できない** |

どちらか一方しか出ない環境でも「どの部分が変わったか」が残ります。色だけにすると、bold の代わりに色を持たない端末で強調が失われます。

### 無効化

`NO_COLOR` 環境変数が設定されている場合、および出力先が TTY でない場合は色も太字も無効化されます。判定は **stdout** に対して行い、stderr の warning / error の判定とは独立しています（stderr の色は v1.0.0 から変更なし）。

```console
$ envdiff .env.example .env.local | less   # 強調なし。パイプ先が TTY でない
$ NO_COLOR=1 envdiff .env.example .env.local   # 強調なし
```

`--json` の出力は従来どおり ANSI を一切含みません。機械可読とはそういうことです。

## 内部の変更

- `comfy-table` の `custom_styling` feature を有効化しました。これがないと ANSI エスケープをただの文字として数え、強調の乗った行だけ列幅が狂って罫線が破綻します
- 依存に `similar` を追加しました（文字粒度の Myers 差分）

## 互換性

v1.0.0 から**破壊的変更はありません**。

| 項目 | 変化 |
| --- | --- |
| 終了コード（0 / 1 / 2） | 変わらない |
| STATUS 語彙 | 変わらない |
| `--json` の形 | 変わらない（ANSI も従来どおり含まない） |
| `--all` / `--json` の意味 | 変わらない |
| パース仕様 | 変わらない |
| テーブルの表示内容 | 強調と色が乗る。値そのものは変わらない |

## スコープ外

v1.0.0 のスコープ外から「テーブル出力の色付け」が外れました。それ以外は従来どおりです。

- サブコマンド（単一責務。`envdiff <A> <B>` のみ）
- 3 ファイル以上の比較
- 変数展開（`${FOO}`）
- 標準入力（`-`）からの読み込み
- 差分の重要度判定
