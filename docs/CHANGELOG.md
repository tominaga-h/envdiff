# Changelog

All notable changes to this project will be documented in this file.

## [1.1.0](release/v1.1.0.md) - 2026-07-17

`changed` 行の「値のどこが変わったか」を見えるようにした。1.0.0 は「この変数が変わった」までしか言わず、`DATABASE_URL` の 40 文字のうちホスト名だけが違うとき、どこを見ればいいかは目視で探すしかなかった。

### Added

- `changed` 行の A/B の値セルに**文字単位の強調**を付ける。A と B で実際に異なる部分だけが太字になり、共通部分は無加工で出る。`only in A` / `only in B` の行には付けない（片側にキーが存在せず「値の中のどこが変わったか」が定義できないため。値を丸ごと太字にすると「値の中のどこかが変わった」と誤読される）。`same` 行も定義上差分がないため付けない
- 位置合わせに LCS（`similar` の文字粒度 Myers 差分）を使う。先頭から 1 文字ずつ突き合わせる実装は挿入・削除が入った時点で破綻し、`localhost`(9) と `db.prod`(7) の長さが違うだけで以降の `:5432/db` が両者に同一で存在するのに差分と判定され、値の大半が太字になって目的が消える
- LCS の結果をそのまま使わず、短い共通部分を差分に吸収してから強調する。LCS が返すのは最小の編集であって人間が読みたいまとまった塊ではないため、素の結果は強調が砕ける
- **差分文字に文字色を付ける（A = 赤 / B = 緑）。** 色が乗るのは太字が乗るのとまったく同じ文字だけで、共通部分は無加工

### Changed

- **テーブルに色を付けないという 1.0.0 の決定を覆した。** 1.0.0 は 3 つの根拠で赤/緑を却下していた。うち「色は情報を足していない」は今も正しく、色は太字と同じ文字に乗るため太字が既に言っていることを繰り返すだけである。承知の上で、A/B の視覚的な区別が読みやすいという理由で採用した。色が果たすのは情報伝達ではなく可読性の役割であり、stderr の色に「唯一の役割を果たす」ことを要求した基準はこの 1 箇所にだけ適用しない
- 「赤緑は色覚特性上もっとも区別しにくい」という根拠は**覆していない。今も正しい**。それでも成立するのは、色が唯一の手掛かりになる場面がないため。太字が色とまったく同じ文字に乗っており、色が見えなくても差分位置は分かる。A/B の区別は列位置・ヘッダー（`.env (A)`）・STATUS 列が担う。色が見えない読者は手掛かりを 1 つ失うが、情報は 1 つも失わない
- 太字と色は冗長に見えるが両方を残す。消える条件が違うため。`NO_COLOR` やパイプでは色が、bold ウェイトを持たないフォントでは太字が消える。色だけにすると `envdiff a b | less` で強調が丸ごと失われる
- 強調・色の TTY 判定は **stdout** に対して行う（stderr の warning / error の判定とは独立）。`NO_COLOR` および stdout が非 TTY のときは無効化する
- `comfy-table` の `custom_styling` feature を有効化した。これがないと ANSI エスケープをただの文字として数え、強調の乗った行だけ列幅が狂って罫線が破綻する
- `--json` の出力は従来どおり ANSI を一切含まない。機械可読とはそういうこと

### Notes

- 強調・色はいずれも**付加情報**であり、終了コード・STATUS 語彙・JSON の形は一切変わらない。1.0.0 からの移行で壊れるものはない
- 太字が出ない端末があることを許容する。SGR 1 の描画は端末依存であり、bold ウェイトを持たないフォントでは無視されることがある。意味は STATUS 列と列位置が担っているため、太字が出なくても情報は失われず手掛かりが減るだけである
- スコープ外から「テーブル出力の色付け」が外れた。それ以外（サブコマンド、3 ファイル以上の比較、変数展開、標準入力、差分の重要度判定）は従来どおりスコープ外

## [1.0.0](release/v1.0.0.md) - 2026-07-16

初回リリース。`.env` 系ファイル 2 つを環境変数のキー単位で比較する CLI。

### Added

#### 比較

- `envdiff <A> <B>`: 2 ファイルを環境変数ごとに比較し、テーブルで出力する。`A` / `B` に「基準」「比較対象」といった非対称な意味付けはせず、単に出力の列順に対応する
- 4 分類: `changed`（両方にあり値が異なる）/ `only in A` / `only in B` / `same`。`only in A` と `only in B` を区別するのは、`.env.example` と `.env` を比べる典型ケースでこの 2 つの意味がまったく違うため（設定漏れ vs 書き忘れ・残骸）
- `same` はデフォルトで非表示。100 個中 3 個違うときに 97 行のノイズを読ませない
- 出力順序はファイルの記載順（アルファベット順にしない）。A のキーを A の行番号順に並べ、`only in B` を B の行番号順で後続させる。ユーザーは差分を見た後に実ファイルを開いて直すため、書かれている順なら出力とファイルを上から突き合わせられる
- 値が空文字の変数（`KEY=`）とキーの不在を区別する。テーブルでは空セルと `-`、JSON では `""` と `null`

#### オプション

- `--all`: 差分のない変数（`same`）も出力に含める
- `--json`: JSON 形式で出力する。差分の重要度をツールが判定しない方針のため、「`only_in_a` だけを失敗にしたい」といったニーズは `jq` で解決する。この逃し弁があるので本体に `--only-missing` のようなフラグを増やさずに済む
- `--all`（表示範囲）と `--json`（出力形式）は直交し、互いの意味を変えない

#### 終了コード

- `diff(1)` の慣習に従う: 差分なし `0` / 差分あり `1` / エラー `2`
- エラーを `1` ではなく `2` に割り当てる。`1` にすると「正常に動作して差分を見つけた」と「ファイルを読めなかった」が呼び出し側から区別できず、パースエラーなのにログに「差分あり」と出れば担当者は存在しない差分を探すことになる
- `--all` / `--json` / 警告は終了コードの判定を変えない

#### パーサ

`.env` に正式な仕様は存在しないため独自の最小仕様を定めた。既存の dotenv クレートには委譲していない（envdiff が必要とする行番号や重複の情報を、それらは捨ててしまうため）。

- `KEY=VALUE` を `=` の最初の出現で分割する（値に `=` を含められる）
- `export KEY=VALUE` の `export` を剥がす
- `#` から行末までをコメントとして無視する。ただしクォート内の `#` はコメントではない
- 値を囲む `'...'` / `"..."` を剥がす。`PORT=3000` と `PORT="3000"` は `same` になる（dotenv が読めば両者は等しく `PORT=3000` であり、クォートの有無は「書かれ方の違い」であって「書かれている内容の違い」ではない）
- `"..."` は `\n` `\r` `\t` `\\` `\"` のみエスケープとして解釈する。`'...'` は一切解釈しない
- 変数展開（`${FOO}`）は行わない。`${` は単なる文字。展開はツールを実行環境に依存させ、CI と手元で違う答えを出す比較ツールになる。また「片方はリファクタされ、片方はハードコードのまま」という人間が知るべき差分を `same` として握り潰す
- 複数行の値に対応する。クォートが閉じないまま行が終わったら閉じるまで次行以降を値として読み続ける（Rails の `master.key`、GCP 認証情報などで実在する形式）
- EOF までクォートが閉じなければパースエラー。メッセージはクォートの**開始行**を指す（「EOF で閉じていません」だけでは 200 行のファイルのどこが原因か探すことになる）
- 重複キーは後勝ちで値を採用し、stderr に警告を出す。重複はほぼ確実にバグ（書いた人は上の行が効くと思っている）だが、パースエラーにはしない — 重複のせいで比較全体が失敗すると本当に知りたかった差分にたどり着けない
- 不正な行（`KEY` / `=VALUE`）はパースエラーで即停止する。読み飛ばすと「変数が片方にない」と誤報告し、ユーザーは実ファイルではなく envdiff のバグを疑うことになる

#### 出力

- `comfy-table` による罫線付きテーブル。長い値は切り詰めず折り返す（切り詰めると「差分があることは分かるが何が違うかは分からない」出力になる）
- テーブルに色を付けない。STATUS 列に既に `only in B` と書かれており色は情報を足さず、赤/緑は「悪い/良い」を含意してツールが差分の重要度を主張することになる
- stderr の warning / error にのみ色を付ける。`NO_COLOR` および stderr が非 TTY のときは無効化する
- 警告は stdout ではなく stderr に出るため、パイプに影響しない

### Notes

- 動作環境: Rust 1.85 以降（2024 edition）。`rust-version` として宣言済み
- MVP のスコープ外: サブコマンド、3 ファイル以上の比較、変数展開、標準入力からの読み込み、差分の重要度判定、テーブル出力の色付け
